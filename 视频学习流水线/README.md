# B站视频下载与处理方案（v2.0）

> 本方案覆盖全部要求：合集下载到D盘、可扩展目录（每视频一目录）、480p试跑+1080p正式、字幕/封面/元数据、AI理解流水线（含Hermes消化）、H.265与音频转码、阿里云盘备份、全程评估。
> 状态：规划完成，待批准后按序执行。
> 指定合集：`https://space.bilibili.com/1997403556/lists/8357740`

---

## 一、目标

1. 将指定合集下载到 D 盘，建成可长期扩展的个人 B 站视频库
2. 视频、字幕、封面、元数据全量保留，每视频一目录
3. 用 AI 理解视频内容，产出结构化笔记、可问答知识库，并交由 Hermes 消化
4. H.265 + 音频转码，压缩空间
5. 字幕与 AI 产物备份到阿里云盘

## 三、目录规划（可扩展 · 每视频一目录）

设计原则：**按 UP主 → 合集 → 单集**三级归档；每集视频自带封面、字幕、元数据；AI 产物与备份文本集中在 `02_导出`；转码产物与源分离。

```
D:\B站下载\                              ← 视频库总根
  ├── 00_配置\
  │    ├── cookies.txt                  ← 登录Cookie（1080p+用）
  │    ├── 已下载存档.txt                ← download-archive 去重记录
  │    ├── logs\                        ← 下载/转码/备份日志
  │    └── 脚本\
  │         ├── transcode.bat           ← H.265+音频 转码脚本
  │         └── backup_aliyun.ps1       ← 阿里云盘备份脚本
  ├── 01_单视频\                         ← 散P（非合集）默认落这里
  │    └── {标题}\
  │         ├── {标题}.mp4
  │         ├── {标题}.webp
  │         ├── {标题}.zh.vtt
  │         └── {标题}.info.json
  ├── 02_导出\                           ← AI 产物 + 待备份文本
  │    ├── 字幕\                        ← 聚合字幕（转 .srt/.txt）
  │    ├── AI笔记\                      ← 每集学习笔记 .md
  │    ├── 问答库\                      ← RAG 向量库（chromadb）
  │    └── 备份清单.txt                 ← 上传哈希清单
  ├── 03_H265存档\                       ← 转码产物（验证后清源）
  └── {UP主昵称}\                        ← 按UP主归档原始下载
       └── {合集名}\
            └── {序号}-{视频标题}\       ← 每视频一目录
                 ├── {序号}-{视频标题}.mp4
                 ├── {序号}-{视频标题}.webp
                 ├── {序号}-{视频标题}.zh.vtt
                 └── {序号}-{视频标题}.info.json
```

## 四、下载流程

### 4.1 安装
```bash
python -m pip install -U yt-dlp
```

### 4.2 探合集（下载前必做）
```bash
yt-dlp -J "URL"   # 元数据：UP主/合集名/视频数
yt-dlp -F "URL"   # 清晰度档位
```

### 4.3 480p 试跑（本期目标，不启用 archive）
```bash
yt-dlp -f "bv*[height<=480]+ba/b" \
  --write-thumbnail --write-subs --sub-langs "zh.*" --write-info-json \
  -o "D:/B站下载/%(uploader)s/%(playlist_title)s/%(playlist_index)02d-%(title)s/%(playlist_index)02d-%(title)s.%(ext)s" \
  --merge-output-format mp4 --sleep-requests 2 --ignore-errors \
  "URL"
```

### 4.4 1080p 正式（补 Cookie 后，启用 archive）
```bash
yt-dlp --cookies "D:/B站下载/00_配置/cookies.txt" \
  -f "bv*[height<=1080]+ba/b" \
  --write-thumbnail --write-subs --sub-langs "zh.*" --write-info-json \
  -o "D:/B站下载/%(uploader)s/%(playlist_title)s/%(playlist_index)02d-%(title)s/%(playlist_index)02d-%(title)s.%(ext)s" \
  --download-archive "D:/B站下载/00_配置/已下载存档.txt" \
  --merge-output-format mp4 --sleep-requests 2 --ignore-errors \
  "URL"
```

### 4.5 画质升级策略
- 480p 试跑**不写存档** → 1080p 用正式存档 → 二者隔离，高清不会被跳过
- 试跑集验证流程后删除，不留重复

### 4.6 附件说明
| 附件 | 来源 | 用途 |
|---|---|---|
| `.zh.vtt` 字幕 | `--write-subs` | AI 理解原料 |
| `.webp` 封面 | `--write-thumbnail` | 海报墙/归档 |
| `.info.json` 元数据 | `--write-info-json` | 标题/UP主/简介/发布时间 |

### 4.7 风控防护
`--sleep-requests 2` 限频、`--ignore-errors` 兜底、限量并发（`-N 2`）。B站风控码 -352 已实测存在，属正常现象。

## 五、AI 理解流水线（六段）

### 阶段1 素材采集
- 有 CC 字幕（B站绝大多数）：下载时已通过 `--write-subs` 获取 ✅ 零成本
- 无字幕的少数集：ffmpeg 抽音频 → 百炼 paraformer 转写（API）或 faster-whisper（本地，需另装）

### 阶段2 清洗对齐
- `.vtt` → `.srt` → `.txt`：去时间戳、拼合断行；工具 `pip install webvtt-py`
- 文本头部写入：标题 / UP主 / 发布时间 / 链接
- 产出：`02_导出\字幕\` 下每集一个 `.txt`

### 阶段3 结构化笔记（核心）
- 输入：整集字幕文本
- 模型：百炼 qwen
- 输出：`02_导出\AI笔记\{合集}\{序号}-{标题}.md`
- 内容结构：章节大纲 / 每章要点 / 代码与命令清单（可复制块）/ 术语表 / 疑问点

### 阶段4 RAG 问答
- 字幕分块 → 百炼 embedding → 存入 `02_导出\问答库\`（chromadb）
- 复用已有 `rag_demo.py` 思路
- 能力：对整批视频提问检索（"这合集里讲 X 的步骤"）

### 阶段5 应用
- 笔记归入 `02_导出\AI笔记\`
- 问答做成 CLI 或小网页

### 阶段6 Hermes 消化（视频知识喂给 Hermes）
- **输入**：阶段3 每集笔记 `.md`
- **消化路径**（待 Hermes 恢复运行后三选一）：
  - A. `skill_manage` 逐条导入为 skill → 后续对话可被直接检索调用（推荐）
  - B. 将 `02_导出\AI笔记\` 整体挂接为 Hermes 检索范围（FTS5），不改笔记结构
  - C. 开对话直接喂入，让 Hermes 理解并归入其知识库
- **产出**：Hermes 可复用的 skill 知识库；后续提问"某视频讲了什么/某命令怎么用"可直接回答
- **前置条件**：Hermes 需先确认可运行（本机实测在 WSL，v0.18.2，DeepSeek 模型）

### 成本
百炼按 token 计费，整集字幕约几万字 → 单集几分钱；境内直连无需代理。

## 六、H.265 + 音频转码（要做）

| 项 | 决定 | 理由 |
|---|---|---|
| 视频编码 | libx265 软编 | 无独显，AMF 核显硬编质量差 |
| 480p 参数 | `-preset medium -crf 28` | 视觉无损级，省约40~50%空间 |
| 1080p 参数 | `-preset medium -crf 26` | 画质优先 |
| 音频 | 默认 `-c:a copy` 不重编码 | 避免有损→有损降质；确要压缩才 AAC 128k |
| 容器 | mp4 + `-tag:v hvc1` | 兼容 Apple/移动端 |
| 网络优化 | `-movflags +faststart` | 在线播放不卡加载 |

### 转码脚本 transcode.bat
```bash
ffmpeg -y -i "%1" \
  -c:v libx265 -preset medium -crf 28 -tag:v hvc1 \
  -c:a copy -map 0:v:0 -map 0:a:0 \
  -movflags +faststart \
  "%2"
```

### 批量与顺序
- 源目录 mp4 → 镜像到 `03_H265存档\`
- 480p 试跑仅验证脚本参数，不全量转（避免 1080p 重下转两遍）；1080p 正式版全量转
- 16 线程分批后台跑，日志进 `00_配置\logs\`

## 七、校验与归档

| 步骤 | 方法 |
|---|---|
| 下载完抽检 | ffprobe 读时长/流信息 + 试播 2~3 集 |
| 转码完校验 | 对比源/转码：时长、分辨率、流数量；抽查播放 |
| 验证通过 | 删除源文件，只留 `03_H265存档` |
| 日志 | 下载/转码/备份统一追加 `00_配置\logs\` |

## 八、阿里云盘备份（字幕 + AI笔记 + 元数据）

### 8.1 范围
只备份小文件文本：`02_导出\字幕\`、`02_导出\AI笔记\`、各视频目录的 `.info.json`。
**不备份视频本体**（体积大、可重新下载物，传云盘性价比低）。

### 8.2 工具（二选一）
| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| 官方客户端（GUI） | 简单，文件夹自动同步 | 不可脚本化 | 求省事选 |
| aliyunpan CLI（开源） | 可脚本化、可定时 | 需登录/装工具 | 推荐（本机实测 Go 版 v0.4.0 在 WSL） |

### 8.3 备份脚本 backup_aliyun.ps1
```powershell
# 1. aliyunpan login          # 首次扫码登录
# 2. 创建远端目录 /备份/B站
# 3. 上传 02_导出\字幕、AI笔记、各集 info.json → /备份/B站/
# 4. 生成/更新 备份清单.txt（时间戳 + 文件哈希，用于校验）
# 5. 上传后按清单对哈希，防静默损坏
```

### 8.4 频率
每批视频处理完成后执行一次；可后续设为定时任务。

## 九、评估

### 9.1 优点
- 全链路复用本机现有件（ffmpeg / Python / 百炼），新增仅 yt-dlp + 云盘工具
- 每视频一目录 + 四件套齐全，AI/转码/备份输入源稳定
- 转码分离目录，验证前源文件零风险
- 云盘只备文本，上传快、成本低、可脚本化

### 9.2 风险与缓解
| 风险 | 缓解 |
|---|---|
| 480p→1080p 双下载 | 试跑不写存档；试跑集验证后删除 |
| H.265 软编耗时（1080p约0.3~0.8x实时） | 后台分批跑 + 日志监控 |
| 音频有损→有损降质 | 默认 `-c:a copy` 不重编码 |
| 阿里云盘无原生 CLI | 官方客户端 或 aliyunpan CLI 二选一 |
| Hermes 损坏不可用 | 单独恢复；恢复前阶段6挂起 |
| 百炼 API 费用 | 仅文本处理，单集几分钱 |
| B站风控（-352） | `--sleep-requests 2` + 限量并发 |
| 画质墙（无 Cookie 仅480p） | 补 Cookie 后重下1080p |

### 9.3 决策表（讨论过、需拍板的项）
| 项 | 现状 | 建议 |
|---|---|---|
| 弹幕抓取 | 未纳入，yt-dlp 不支持需另配工具 | 学习类视频弹幕信息量一般，默认不做 |
| Jellyfin 建库 | 未纳入 | 攒多了再考虑，非必需 |

### 9.4 明确不做
- 视频本体传阿里云盘
- 弹幕抓取（默认）
- Jellyfin 建库（当前）
- 无独显下的 AMF 硬编
